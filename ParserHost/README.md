# Uzumaki parser host

An out-of-process JVM process that runs the [Kotatsu parser
library](https://github.com/Kotatsu-Redo/kotatsu-parsers-redo) and exposes it to
the macOS app over newline-delimited JSON on stdin/stdout.

**Why a separate process.** The Kotatsu parsers are Kotlin/JVM only, and there
are ~1370 of them. They contain no Android APIs — they ask a host for an HTTP
client, a cookie jar, a JS engine, a bitmap implementation and some config. So
the cheapest way to reuse them all on macOS is to implement that host once and
talk to it over a pipe, rather than port a decade of accumulated scraping.

**Why this matters in practice.** Verified against real sources: MangaDex (842
chapters) and MangaPill (1212 chapters) both work end-to-end through this host on
macOS — browse, search, details, and page resolution.

---

## Layout

| Path | Purpose |
| --- | --- |
| `src/main/kotlin/uzumaki/host/Main.kt` | stdio loop, NDJSON framing |
| `src/main/kotlin/uzumaki/host/ParserHost.kt` | method dispatch and model mapping |
| `src/main/kotlin/uzumaki/host/HostContext.kt` | `MangaLoaderContext` implementation (OkHttp, cookies, AWT bitmaps) |
| `src/main/kotlin/uzumaki/host/Json.kt` | small JSON helpers |

## Prerequisites

A **JDK 17** is mandatory. Gradle comes from the bundled wrapper.

```sh
brew install --cask temurin@17
export JAVA_HOME="$(/usr/libexec/java_home -v 17)"
```

## 1. Build the parsers library

The parser registry (`MangaParserSource`, 1370 entries) is **generated by KSP**,
so it has to be built, not downloaded. Pin a commit of the fork and publish it
locally:

```sh
cd /path/to/kotatsu-parsers-redo-master
./gradlew publishToMavenLocal     # produces org.koitharu:kotatsu-parsers:1.0
```

## 2. Build the host

```sh
cd ParserHost
./gradlew fatJar                  # build/libs/uzumaki-parser-host-all.jar
```

The fat jar exists because the bundled runtime ships no third-party jars.

## 3. Bundle a trimmed runtime (for distribution)

Verified working on JDK 17 — the trimmed runtime is **45 MB** and successfully
loads the host and performs real network requests:

```sh
jlink \
  --add-modules java.base,java.desktop,java.logging,java.naming,java.management,java.xml,jdk.crypto.ec,jdk.unsupported \
  --strip-debug --no-header-files --no-man-pages --compress=2 \
  --output runtime
```

Note `--compress=2` is the JDK 17 syntax; JDK 21+ uses `--compress=zip-6`.

`java.desktop` is needed for the AWT `BufferedImage` image-descrambling path;
`jdk.crypto.ec` is needed for TLS. After trimming, **run the host on the result
and exercise a real source** — `jlink` silently omits anything not listed, and
the failure mode is a `NoClassDefFoundError` at runtime, not at build time.

```sh
printf '%s\n%s\n' '{"id":1,"method":"ping"}' \
  '{"id":2,"method":"list","params":{"key":"MANGAPILL","offset":0,"query":"berserk"}}' \
  | ./runtime/bin/java -jar build/libs/uzumaki-parser-host-all.jar
```

Bundled layout the app expects:

```
Uzumaki.app/Contents/Resources/ParserHost/
  runtime/                      # jlink output
  uzumaki-parser-host-all.jar
```

Shipping this means signing every Mach-O in `runtime/` with your team ID and
adding `com.apple.security.cs.allow-jit` to the app's entitlements; a sandboxed
child process also needs `com.apple.security.inherit`.

## Protocol

One JSON object per line. Requests carry an `id` and a `method`; responses carry
the same `id` plus either `result` or `error`. `{"event":"ready"}` is emitted
first.

| Method | Params | Result |
| --- | --- | --- |
| `ping` | – | `{protocol, sourceCount}` |
| `sources` | – | `{items: [{key,title,locale,contentType,broken}]}` |
| `list` | `{key, offset, sort?, query?, states?, contentRatings?, types?, demographics?, yearFrom?, yearTo?, author?}` | `{items: [manga]}` |
| `details` | `{key, manga}` | `manga` including `chapters` |
| `pages` | `{key, chapter}` | `{items: [{id,url,resolvedUrl,preview}]}` |
| `filterOptions` | `{key}` | `{sortOrders, capabilities, options}` |

`manga` and `chapter` round-trip the objects returned by `list`/`details`, since
the parsers need them back to fetch details and pages.

`stdout` is redirected to `stderr` immediately at startup: parsers occasionally
print, and a stray line would corrupt the protocol stream.

## Known gaps

* **JavaScript sources are unsupported.** `evaluateJs` throws, so sources that
  need script execution (e.g. ComicK) fail with an `unsupported` error. Adding a
  JS engine behind that one method is all that is required.
* **WebView-dependent sources are unsupported** (`interceptWebViewRequests`),
  as is browser-based Cloudflare auth. Sources that need them should be excluded
  or marked broken.
* **~428 of 1370 sources are flagged `isBroken` upstream**, and several that are
  not flagged still fail (Cloudflare, moved domains, 5xx). Curate empirically.
* **Page images may need host-side fetching.** Some CDNs reject direct requests
  because the parser's OkHttp interceptors and cookie jar are not applied. Page
  bytes should be fetched through the host when direct fetching 403s.
