- Leverages Swift's strong type system and avoids force unwrapping. Confidence: 0.85

- Follows SwiftUI patterns with clear separation of concerns. Confidence: 0.8
- Adds descriptive comments for complex or non-obvious logic. Confidence: 0.75
- Uses the Swift Testing framework for unit tests and the XCUIAutomation framework for UI tests. Confidence: 0.85
- Wants changes limited strictly to what was asked: do not make unrelated changes to other parts of the project. Confidence: 0.85

- When generating markdown tables, always uses leading and trailing pipes on every row (e.g. `| Name | Age |`, never `Name | Age`). Confidence: 0.9

- Explicitly separates investigation and planning from implementation: uses plan mode for substantial features (designs a written plan first, has it approved, and only then writes code), and when asked to "not implement yet" / "not modify project files", produces analysis and recommendations only, waiting for a follow-up before writing code. Confidence: 0.8

- Prefers self-contained deliverables that work out of the box: bundle the required runtime with the app rather than depending on users installing system prerequisites (e.g. a system JVM); runtime resources belong inside the .app bundle (Contents/Resources) because the sandboxed app cannot read files outside its container. Confidence: 0.7

Confidence: 0.6
